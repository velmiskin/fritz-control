Технический стек\n\n| Компонент | Технология |\n|---|---|\n| Контроллер | ESP32-WROOM-32E |\n| Прошивка | MicroPython |\n| Разработка | VS Code + Windows |\n| Веб-сервер | `uasyncio` |\n| Протокол роутера | TR-064 / SOAP |\n| Формат обмена | XML / JSON |\n| Интерфейс | HTML5 / CSS / JavaScript |\n| Настройки | JSON + Flash |\n| Время | NTP |\n| Удалённый доступ | WireGuard VPN |\n| Контроль версий | Git |\n\n**Ограничения оборудования:** 520 KB SRAM — это не вся память, доступная Python-приложению. Блокировка и разблокировка\n\n<badge color=\"secondary\">Critical functionality</badge>\n\nЭто центральная часть проекта.\n\nЗадачи:\n- [ ] Реализовать `DisallowWANAccessByIP`.\n- [ ] Реализовать `GetWANAccessByIP`.\n- [ ] Проверять результат каждой команды.\n- [ ] Добавить блокировку и разблокировку одного устройства.\n- [ ] Добавить массовую блокировку.\n- [ ] Проверять фактический статус после команды.\n- [ ] Обрабатывать ошибки роутера и тайм-ауты.\n- [ ] Не допускать повторного выполнения одной операции.\n\nОсобенности:\n- Команды HostFilter используют IPv4.\n- Для управления нужен IP, зарегистрированный в FRITZ!Box.\n- Желательно закрепить IP-адреса за устройствами через DHCP.\n- FRITZ!Box применяет изменение асинхронно, поэтому статус нужно перепроверять.\n\n**Результат:** можно заблокировать выбранное устройство и достоверно проверить результат. <Cite refs={[\"turn301638view0\"]}/>\n\n### Этап 3. Временный доступ и расписания\n\n<badge color=\"secondary\">Smart access control</badge>\n\nЭто одна из главных функций FritzControl.\n\nЗадачи:\n- [ ] Доступ на 15 минут.\n- [ ] Доступ на 30 минут.\n- [ ] Доступ на 1 час.\n- [ ] Доступ на 2 часа.\n- [ ] Произвольная продолжительность.\n- [ ] Продление доступа.\n- [ ] Досрочная блокировка.\n- [ ] Расписание по дням недели.\n- [ ] Автоматическая блокировка по окончании времени.\n- [ ] Восстановление активных таймеров после перезагрузки.\n\n**Важное техническое решение:**\n\nУ FRITZ!Box есть два подхода:\n\n1. Собственный таймер ESP32: временно снимает блокировку через `DisallowWANAccessByIP`, а по окончании срока снова устанавливает её.\n2. Встроенные Tickets и профили доступа FRITZ!Box: позволяют использовать механизм дополнительного времени.\n\nУ AVM есть `AddTicketTimeToHostEntryByIP`, но он работает только с профилями, в которых настроено расписание или временной бюджет. Время определяется настройками профиля, а не произвольным числом минут из веб-панели. Поэтому для MVP используем первый подход, а Tickets исследуем отдельно. <Cite refs={[\"turn301638view0\"]}/>\n\n**Результат:** временный доступ работает независимо от открытого браузера и сохраняется после перезагрузки ESP32.\n\n### Этап 4. Правила разработки для AI Coding Agent\n\nЭто важно, чтобы агент не пытался сделать всё сразу и не расходовал память ESP32.\n\nЯ предлагаю зафиксировать следующие правила:\n\n1. Только MicroPython, без Arduino C++.\n2. Не использовать библиотеки, рассчитанные на полноценный Linux/Python.\n3. Не использовать тяжёлые HTML-фреймворки.\n4. Веб-интерфейс хранить отдельно от Python-кода.\n5. Не блокировать основной event loop длительными операциями.\n6. SOAP-запросы выполнять последовательно, с тайм-аутами.\n7. Не хранить пароли в Git.\n8. Каждую функцию проверять отдельно.\n9. Не менять настройки FRITZ!Box без явного действия пользователя.\n10. Все операции блокировки должны иметь проверку результата.\n\nДополнительно: необходимо предусмотреть закрепление IP за MAC. В первой версии управление доступом будет IPv4-only, поскольку документированный HostFilter использует `NewIPv4Address`. Возможность полноценного контроля IPv6 нужно исследовать отдельно.\n\n## 6.
